# 自然语言 goal 触发

目标：让用户说人话就能进入“做完再汇报”的模式，不需要记 `/goal`；同时避免误触发。

## 强触发（有明确任务时，自动建 goal）

以下短语视为“强触发”，但必须同时存在一个明确任务/目标：

- 直接做完
- 全部做完再汇报
- 做完再汇报
- 不用问我，做完再说
- 别问我，直接做完
- 一口气做完
- 按这个做完
- 按这个执行到完成
- 从头做到尾
- 完成前不要停
- 你全权处理，做完给结果
- 交给你了，直接做完
- 直接做到能用
- finish it
- just do it, don't ask
- take it to completion

动作：

1. 如果已有 active goal：继续该 goal，不重复创建。
2. 如果没有 goal，且任务是**多步/长任务**：调用 `create_goal`，目标写“完成什么 + 验收标准 + 完成前不要停”。
3. 如果任务只是**一步/很小**：不创建 goal，直接做完，最后报告。
4. 创建后只用一句话告知“我按完成目标执行，最后统一汇报”，不询问确认。

## 中触发（任务明确但较短，不建 goal，也不问）

- 搞定它
- 全部搞定
- 做到能用
- 按计划执行
- 你自己决定
- 看着办，做完给我

处理：直接执行，不建 goal；如果发现任务实际变成多步，再升级为 goal。

## 弱词（不能单独触发 goal）

- 继续
- 开始
- 做吧
- 完成
- 全部
- 直接
- 好的
- 可以

这些词只在**已有任务/已有 goal**时表示继续，不单独创建新 goal。

## 明确排除（不能触发 goal）

- 只是讨论 / 先给方案 / 先别做
- 不要建 goal / 不要目标模式
- 停 / 取消 / 暂停
- 只回答，不要执行
- 引用别人的话、代码块、示例里的短语
- “直接”单独出现
- “完成”单独出现

## 没有明确任务时

用户说了强触发词，但没说什么任务：

- 只问一句：“要完成的具体是什么？”
- 不要猜测，不要建空 goal。
- 这是少数允许的澄清。

## 已有 goal 时

- 用户说继续/做完/搞定：继续当前 goal
- 用户说停/暂停：`/goal pause`
- 用户说取消：`/goal clear`
- 用户给新目标：先确认旧 goal 是否完成/暂停/清除，避免一个会话两个 goal。

## 创建 goal 的写法

```text
目标：完成<具体交付>。
验收：<可验证标准>。
约束：<不能做什么/必须保留什么>。
完成前不要停；只有破坏性操作、账号/付费/法律、两个互斥产品方向、验收完全不清才允许提问。
```

## 示例

用户：

```text
这个工具你直接做完，全部做完再汇报。
```

处理：

- 有明确任务 → 建 goal
- 不问确认
- 一直做到验收
- 最后报告

用户：

```text
继续。
```

处理：

- 有 active goal → 继续
- 没有 goal → 这只是继续对话，不建 goal

用户：

```text
先给方案，不要做。
```

处理：

- 不建 goal
- 只出方案
