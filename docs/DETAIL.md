# Noncoder engineering

把“产品想法”变成“能用的软件”，但不把技术选择题丢给用户。

## 安装

### 本机目录安装

在 DSH 里使用插件管理器安装这个目录：

```text
D:\AI\dsh-noncoder-engineering-plugin
```

安装后重启/刷新会话，在 **Plugins** 里应看到 **Noncoder engineering**。

### GitHub / npm 安装

将本目录发布为 Git 仓库或 npm 包后，用 DSH 的插件安装入口安装。

## 使用

技能名：

```text
noncoder-engineering
```

调用示例：

```text
用非程序员工程助手，auto：帮我做一个记账小工具。
```

```text
用非程序员工程助手，guided：我想做一个管理角色和分镜的桌面工具。
```

```text
用非程序员工程助手，strict：帮我完整规划这个项目。
```

## 模式

| 模式 | 行为 |
|---|---|
| `auto` | 默认。不问，直接做，最后报告 |
| `guided` | 开头最多 3 个产品问题，然后自动做 |
| `strict` | 多问一些产品/验收问题，仍然不问技术实现 |

## goal 模式

如果已经用 `/goal` 设定目标，或已经给出完整步骤/验收标准：

- 不做开场提问
- 不逐步确认
- 直接执行到完成
- 最后统一汇报：完成内容、用法、替用户做的决定、问题、建议

## 限制

- 嵌入式技能与用户目录里的同名 `noncoder-engineering` 技能可能冲突；安装插件前建议移除手动复制版。
- 插件只提供指令，不包含执行引擎；实际能力取决于当前 DSH 配置和工具。
- 它不会替代测试、安全审计或人工验收。
