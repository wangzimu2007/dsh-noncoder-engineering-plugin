# Noncoder engineering

把“产品想法”变成“能用的软件”，但不把技术选择题丢给用户。

## 版本 1.4

新增自然语言 goal 触发，不用记 `/goal`。

### 强触发短语（需要任务明确）

- 直接做完
- 全部做完再汇报
- 做完再汇报
- 不用问我，做完再说
- 别问我，直接做完
- 一口气做完
- 按这个做完
- 按这个执行到完成
- 从头做到尾
- 完成前不要停
- 你全权处理，做完给结果
- finish it
- just do it, don't ask

### 不单独触发的词

继续、开始、做吧、完成、全部、直接、好的、可以。

这些只在已有任务/已有 goal 时表示继续，不会创建新 goal。

### v1.4 自动阶段审查

- 长任务每个里程碑自动起 fresh reviewer
- 先跑测试，再审查逻辑 bug、边界、安全与验收不符
- BLOCKER 不修完不能进入下一阶段
- 中文触发：审查一下/代码审查/复查逻辑/检查有没有 bug/看看有没有安全问题
- 排除：检查配置/检查环境/检查文件/检查端口/看看日志

## 安装

用 DSH 插件管理器安装这个目录：

```text
D:\AI\dsh-noncoder-engineering-plugin
```

安装后在 **Plugins** 里应看到 **Noncoder engineering**。

## 使用

```text
用非程序员工程助手，auto：帮我做一个记账小工具。
```

```text
这个工具你直接做完，全部做完再汇报。
```

有明确任务 + 强触发短语时，会自动进入完成目标模式，最后统一汇报。

## 模式

| 模式 | 行为 |
|---|---|
| `auto` | 默认。不问，直接做，最后报告 |
| `guided` | 开头最多 3 个产品问题，然后自动做 |
| `strict` | 多问产品/验收问题，仍然不问技术实现 |

## 限制

- 嵌入式技能与手动复制的同名技能冲突；不要在同一个 DSH 里同时装两份。
- 插件只提供指令，不包含执行引擎；实际能力取决于 DSH 配置和工具。
- 它不会替代测试、安全审计或人工验收。
